# Changelog v0.2.0

## [v0.2.0] - UNRELEASED

### Backend
#### [MOD] Endpoint Zona Austral
- Implementado cálculo automático de días en Zona Austral (Lat <= -50º S).
- **Corrección**: Se normalizaron los límites de las etapas de navegación para que sean inclusivos del día completo (00:00:00 - 23:59:59), solucionando el error donde se omitían puntos de trayectoria el último día de arribo.
- **Mejora**: El endpoint ahora devuelve un desglose detallado por cada etapa de la marea, incluyendo el total de días y la lista de fechas detectadas por etapa.
- Requisito de integridad: Mínimo 2 puntos de trayectoria por día local dentro de cada etapa.
- Nuevo endpoint: `GET /mareas/:id/zona-austral`.

#### [TEST] Integridad de Datos
- Añadidas pruebas unitarias (`tracking-import-tz.spec.ts`) para garantizar que las fechas de monitoreo CSV (en UTC) se interpreten correctamente independientemente de la zona horaria del servidor.

### 🛠️ Mejoras y Refactorizaciones
- **Experiencia de Usuario (Wizard)**: 
    - Unificación de mensajes de error dentro de los componentes `SearchableSelect` y `DatePicker`, eliminando redundancia visual.
    - Limpieza reactiva de errores al corregir campos individuales.
    - Herencia automática de fechas y puerto base en el paso de etapas.
- **Robustez del Frontend**: Refactorización completa de los tests del diálogo de nueva marea para manejar lógicas asíncronas complejas y estados de Pinia.

### 🧪 Testing
- **Backend (Service)**: Actualización de la suite de pruebas de `MareasService` para cubrir las nuevas reglas de negocio de disponibilidad y validación de año.
- **Backend (Integridad DB)**: Nueva suite de pruebas `marea-db-integrity.spec.ts` que valida físicamente el rechazo de solapamientos (max 1 por estado) y la coherencia de fechas en PostgreSQL.
- **Saneamiento de Salida**: Eliminación de logs invasivos en `AuditService` y `PrismaService` para asegurar una salida de tests profesional y silenciosa.
- **Frontend**: 100% de pasaje en las pruebas unitarias de `NuevaMareaDialog.spec.ts` integrando mocks asíncronas y sincronización de ciclos de renderizado.

### 🏰 Integridad de Base de Datos (Defensa en Profundidad)
- **Constraints de Año**: Implementación de `CHECK CONSTRAINT` flexible que admite zarpadas en enero del año siguiente para misiones de fin de año.
- **Triggers de Disponibilidad Selectiva**: 
    - **Permisivo**: Permite tener una marea navegando (`EN_EJECUCION`) y una marea reservada (`DESIGNADA`) al mismo tiempo.
    - **Restrictivo**: Prohíbe la duplicidad de reservas (max 1 `DESIGNADA`) o de operaciones físicas (max 1 `EN_EJECUCION`) para el mismo buque u observador.


### ✨ Nuevas Funcionalidades
- **Campo matricula_siop**: Se añadió un nuevo campo `matricula_siop` a la entidad `Buque` para separar la identificación de sistemas externos de la matrícula oficial del buque.

### 🛠️ Mejoras y Refactorizaciones
- **Importación de Trayectorias**: El proceso de importación masiva desde SIOP ahora utiliza exclusivamente el campo `matricula_siop` para vincular puntos de trayectoria, evitando que se sobrescriban las correcciones manuales en el campo `matricula`.
- **Sincronización Automática**: El sistema actualiza automáticamente la `matricula_siop` si un buque es identificado por nombre, asegurando la consistencia de futuras importaciones sin afectar los datos oficiales.

### 🧪 Testing
- **Validación de SIOP**: Implementación de pruebas unitarias específicas para garantizar que la búsqueda por identificación SIOP y el fallback por nombre no afecten el campo de matrícula oficial.

 
## 2026-02-05 - Sistema de Acciones Genéricas y Consistencia Operativa

### ✨ Nuevas Funcionalidades
- **Diálogo Genérico de Acciones**: Implementación de un componente dinámico (`MareaGenericActionDialog.vue`) que gestiona transiciones de estado sin diálogos específicos, informando el próximo estado y capturando notas obligatorias.
- **Metadatos Dinámicos en Backend**: El servicio de mareas ahora retorna metadatos de transición (`toStateName`, `requiresNotes`) facilitando la configuración automática de la interfaz.
- **Cancelación en Detalle Operativo**: Añadida la acción "CANCELAR" en `MareaOperativaDetalleView.vue` para garantizar paridad funcional con el panel lateral.

### 🛠️ Mejoras y Refactorizaciones
- **Registro de Movimientos**: Se corrigió el flujo en la gestión de alertas para asegurar que los cambios de etapa utilicen `executeAction`, garantizando el registro histórico de movimientos en la base de datos.
- **Validación de Notas**: Implementada lógica de validación dinámica que exige comentarios en acciones críticas (ej. rechazos) y los permite como opcionales en otras.
- **Copia de Seguridad**: Optimizada la descarga de archivos grandes (>150MB) reduciendo el nivel de compresión y desactivando el buffering en proxies.
- **Feedback de Descarga**: Añadido overlay de procesamiento en `BackupView.vue` para informar al usuario durante la generación del archivo ZIP.

### 🧪 Testing
- **Cobertura de Frontend**: Implementación de suite de pruebas unitarias para el diálogo genérico utilizando Vitest, cubriendo renderizado condicional, validaciones y emisiones de eventos.
- **Cobertura de Backend**: Extensión de pruebas en Jest para validar el correcto enriquecimiento del contexto de marea y la lógica de negocio de las transiciones.

 ## 2026-02-08 - Unificación de Inteligencia y Metadata Estándar

### ✨ Nuevas Funcionalidades
- **Inteligencia Centralizada**: Implementación de `EventCorrelationService.evaluateEventContext` que unifica las reglas de negocio para todas las fuentes de alertas (PNA y Tracking).
    - **Validación Cronológica**: Bloqueo automático de eventos antiguos o fuera de secuencia respecto a lo ya registrado.
    - **Recomendaciones de Cierre**: Sugerencia proactiva de "Finalizar Marea" cuando se detecta un arribo y existe una marea designada esperando.
- **Detección de Discrepancias (PNA)**: Los reportes de Prefectura ahora también disparan alertas de "Discrepancia en Puerto" y "Incongruencia de Fecha" si difieren de los datos cargados manualmente, igualando la capacidad del Tracking.
- **Soporte Multi-fuente (Source Stacking)**: Capacidad de "apilar" múltiples orígenes en una única alerta. La interfaz ahora muestra badges combinados (ej. PNA + Tracking) para indicar eventos validados por múltiples sistemas.

### 🛠️ Mejoras y Refactorizaciones
- **Estandarización de Metadata**: Refactorización completa de `PnaApiService` para utilizar la interfaz `AlertMetadata`, asegurando consistencia de datos para procesos de auditoría.
- **Robustez en Deduplicación**: Mejora en los algoritmos de búsqueda cruzada para evitar duplicados entre orígenes con diferentes precisiones temporales.
- **Interfaz de Usuario (Inbox)**: 
    - `InboxAlertCard`: Nueva lógica de renderizado para múltiples badges de origen.
    - `AlertManagementDialog`: Unificación de colores y etiquetas de origen (PNA: Naranja + Icono Buque, Tracking: Verde).

### 🐛 Correcciones de Errores
- **Timezone en Alertas**: Se corrigió un bug en `AlertsService` donde la `fechaDetectada` se reiniciaba a la hora del servidor en lugar de conservar la del evento original, mejorando la precisión de la deduplicación histórica.
- **Tipado de IDs**: Ajuste en la interfaz de metadatos para soportar IDs alfanuméricos provenientes de la API de PNA.

## 2026-02-07 - Integración de API PNA y Control Manual de Tareas
 
 ### ✨ Nuevas Funcionalidades
 - **Detección de Movimientos (API PNA)**: Implementación de la integración oficial con Prefectura Naval Argentina para capturar eventos de zarpada y arribo.
     - **Modelo de Auditoría**: Nuevo modelo `PnaApiSnapshot` que almacena datos crudos para trazabilidad total.
     - **Lógica de Convergencia (Source Stacking)**: El sistema ahora unifica alertas de múltiples fuentes (VMS y PNA), permitiendo que un evento detectado por satélite sea validado oficialmente por la autoridad portuaria.
     - **Refinamiento de Inteligencia**: Reducción del 95% de ruido mediante filtros de marea activa (`DESIGNADA`/`EN_EJECUCION`) y validación automática contra etapas de marea ya registradas manualmente.
     - **Enriquecimiento de Metadata**: Estandarización de títulos y descripciones con metadata completa (`type`, `subTipo`, `eventDate`, `portName`, etc.) para plena compatibilidad con los sistemas de Tracking y Access.
 - **Control Manual de Tareas**: Habilitada la posibilidad de disparar sincronizaciones a demanda desde el Dashboard Administrativo.
     - Nuevos botones para sincronización de PNA y Buques.
     - Sistema de prevención de duplicados en la cola de ejecución.
 
 ### 🛠️ Mejoras y Refactorizaciones
 - **Source Validation**: El servicio de alertas ahora permite inyectar fuentes de validación adicionales a una alerta existente sin duplicar la notificación.
 - **Vínculo con Marea**: Las alertas detectadas por PNA se vinculan automáticamente a la marea activa del buque, facilitando la gestión operativa.
 
 ### 🧪 Testing
 - **Validación de Reglas**: Pruebas exitosas con dataset de 507 reportes oficiales, verificando la efectividad de los filtros de ruido y la idempotencia del proceso.
