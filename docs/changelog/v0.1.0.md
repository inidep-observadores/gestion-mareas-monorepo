# Changelog v0.1.0

## [v0.1.0] - UNRELEASED

### Backend
#### [MOD] Endpoint Zona Austral
- Implementado cálculo automático de días en Zona Austral (Lat <= -50º S).
- **Corrección**: Se normalizaron los límites de las etapas de navegación para que sean inclusivos del día completo (00:00:00 - 23:59:59), solucionando el error donde se omitían puntos de trayectoria el último día de arribo.
- **Mejora**: El endpoint ahora devuelve un desglose detallado por cada etapa de la marea, incluyendo el total de días y la lista de fechas detectadas por etapa.
- Requisito de integridad: Mínimo 2 puntos de trayectoria por día local dentro de cada etapa.
- Nuevo endpoint: `GET /mareas/:id/zona-austral`.

#### [TEST] Integridad de Datos
- Añadidas pruebas unitarias (`tracking-import-tz.spec.ts`) para garantizar que las fechas de monitoreo CSV (en UTC) se interpreten correctamente independientemente de la zona horaria del servidor.

#### [NEW] Integración con API Externa de Buques
- **Cliente Fishery**: Implementado sistema de adaptadores para consumir datos oficiales de buques desde la API del Ministerio de Pesca.
  - Arquitectura basada en patrón Strategy con `FisheryApiAdapter` (producción) y `FisheryMockAdapter` (desarrollo/testing).
  - Configuración mediante variables de entorno: `FISHERY_API_ENDPOINT`, `FISHERY_API_TIMEOUT`, `USE_MOCK_FISHERY_API`.
- **Sincronización de Datos**: Nuevo servicio `VesselSyncService` que actualiza automáticamente la información de buques.
  - Sincronización inteligente basada en umbral configurable (`VESSEL_SYNC_THRESHOLD_DAYS`, default: 7 días).
  - Enriquecimiento de datos: matrícula, bandera, año de construcción, MMSI, tipo de buque, señal distintiva, dimensiones (eslora, manga, puntal), arqueo, calado, puerto de asiento, dotación mínima, y estado de registro.
- **Migración de Base de Datos**: Añadidos 15 nuevos campos a la tabla `buques` para almacenar datos oficiales.
  - Migración aditiva segura aplicada sin pérdida de datos existentes.
  - Nuevo campo `fecha_ultima_actualizacion_api` para tracking de sincronizaciones.

#### [NEW] Sistema Genérico de Tareas Programadas (Job Queue)
- **Infraestructura de Tareas**: Implementado sistema escalable de procesamiento asíncrono de trabajos en segundo plano.
  - Nueva tabla `job_queue` con soporte para múltiples tipos de tareas, reintentos automáticos, priorización y backoff exponencial.
  - `SchedulerService` con bloqueo distribuido usando `system_status` para prevenir ejecución concurrente en entornos multi-instancia.
  - Configuración mediante cron expressions (`JOB_SCHEDULER_INTERVAL_CRON`).
- **Procesadores de Tareas**: Arquitectura extensible basada en la interfaz `JobProcessor`.
  - `VesselSyncProcessor`: Procesa sincronizaciones de buques con rate limiting configurable (`VESSEL_SYNC_RATE_LIMIT_MS`).
  - Preparado para futuras tareas de sincronización de trayectorias y otros procesos batch.
- **Ventajas**:
  - Evita saturación de APIs externas mediante control de tasa de peticiones.
  - No bloquea operaciones críticas (ej: importación CSV).
  - Reintentos automáticos con backoff exponencial ante fallos transitorios.
  - Monitoreo centralizado del estado de todas las tareas.

#### [MOD] Disponibilidad de Observadores
- **Validación Estricta**: Se impide la asignación de observadores que se encuentren en mareas `EN_EJECUCION` o `DESIGNADA`. Anteriormente solo se validaba el estado `DESIGNADA`.
- **Nuevo Filtro**: El endpoint `GET /catalogos/observadores` ahora soporta `?soloDisponibles=true` para excluir observadores ocupados o con impedimentos.

### Frontend
- **Refinamiento de Diálogo**: Optimización del flujo de usuario en `GestionEtapasMareaDialog.vue`.
  - La sección de **Zona Austral** ahora solo es visible en el modo `FINALIZAR`.
  - La sección de **Etapas** se despliega automáticamente en el modo `EDITAR` para reducir clics innecesarios.
- **Estabilidad**: Añadidas pruebas unitarias para componentes colapsables y validación de cronología de etapas.
- **Alta de Marea**: El diálogo de creación ahora filtra automáticamente la lista de observadores, mostrando únicamente aquellos realmente disponibles.

### General
- Refinamiento de reglas de integridad de base de datos para la gestión de mareas.
- Mejora en los tiempos de verificación de disponibilidad de buques y observadores.
