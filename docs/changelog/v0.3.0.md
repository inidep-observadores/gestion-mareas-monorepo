# Changelog v0.3.0

## [v0.3.0] - UNRELEASED

### Backend

#### [NEW] Integración con API Externa de Buques
- **Cliente Fishery**: Implementado sistema de adaptadores para consumir datos oficiales de buques desde la API del Ministerio de Pesca.
  - Arquitectura basada en patrón Strategy con `FisheryApiAdapter` (producción) y `FisheryMockAdapter` (desarrollo/testing).
  - Configuración mediante variables de entorno: `FISHERY_API_ENDPOINT`, `FISHERY_API_TIMEOUT`, `USE_MOCK_FISHERY_API`.
- **Sincronización de Datos**: Nuevo servicio `VesselSyncService` que actualiza automáticamente la información de buques.
  - Sincronización inteligente basada en umbral configurable (`VESSEL_SYNC_THRESHOLD_DAYS`, default: 7 días).
  - Enriquecimiento de datos: matrícula, bandera, año de construcción, MMSI, tipo de buque, señal distintiva, dimensiones (eslora, manga, puntal), arqueo, calado, puerto de asiento, dotación mínima, y estado de registro.
- **Migración de Base de Datos**: Añadidos 15 nuevos campos a la tabla `buques` para almacenar datos oficiales.
  - Migración aditiva segura aplicada sin pérdida de datos existentes.
  - Nuevo campo `fecha_ultima_actualizacion_api` para tracking de sincronizaciones.

#### [NEW] Sistema Genérico de Tareas Programadas (Job Queue)
- **Infraestructura de Tareas**: Implementado sistema escalable de procesamiento asíncrono de trabajos en segundo plano.
  - Nueva tabla `job_queue` con soporte para múltiples tipos de tareas, reintentos automáticos, priorización y backoff exponencial.
  - `SchedulerService` con bloqueo distribuido usando `system_status` para prevenir ejecución concurrente en entornos multi-instancia.
  - Configuración mediante cron expressions (`JOB_SCHEDULER_INTERVAL_CRON`).
- **Evolución de Base de Datos**: Actualización del modelo `JobQueue` para soportar analíticas avanzadas.
  - Implementación de tipos enumerados nativos (`JobStatus`, `JobType`).
  - Nuevos campos de diagnóstico: `duration` (ms), `result` (JSON), `stack_trace` y `error_message`.
  - Índices optimizados para consultas de estadísticas y series temporales.
- **Backend Analítico y API de Administración**:
  - `JobQueueStatsService`: Servicio dedicado para el cálculo eficiente de KPIs, rendimiento por tipo de tarea y distribución de errores.
  - `JobQueueController`: Endpoints de gestión y monitoreo protegidos mediante el decorador `@Auth(ValidRoles.admin)`.
  - Funcionalidades: Listado paginado con filtros, detalle técnico de ejecución, reintento manual de tareas fallidas y cancelación.
- **Procesadores de Tareas**: Arquitectura extensible basada en la interfaz `JobProcessor`.
  - `VesselSyncProcessor`: Procesa sincronizaciones de buques con rate limiting configurable (`VESSEL_SYNC_RATE_LIMIT_MS`).
  - Preparado para futuras tareas de sincronización de trayectorias y procesos batch.

#### [FIX] Corrección de Búsqueda en API de Buques
- **Problema**: El sistema intentaba buscar buques por matrícula (no soportado por API PNA)
- **Solución**: Implementado orden de búsqueda correcto
  - **1º Búsqueda por ID MBPC** (más preciso)
  - **2º Fallback por MMSI** (nuevo método implementado)
  - **3º Fallback por nombre** (última opción)
- **Mejoras en payload del job**:
  - Añadido `nombreBuque`, `idMbpc` y `mmsi` al payload
  - Logs mejorados con información detallada de búsqueda
- **Impacto**: Las sincronizaciones ahora funcionan correctamente con la API real de PNA

#### [FEAT] Mejoras en Dashboard de Gestión de Tareas
- **Ordenamiento por Columnas**: Implementada funcionalidad de ordenamiento clickeable en el datatable de tareas.
  - Columnas ordenables: Tipo, Estado, Intentos, Última Ejecución, Duración
  - Indicador visual con icono chevron que rota según dirección (asc/desc)
  - Orden por defecto: Fecha de creación (más reciente primero)
- **Filtro por Tipo de Tarea**: Agregado selector dropdown en el gráfico "Evolución de Tareas".
  - Permite filtrar datos por tipo específico o ver todos los tipos
  - Filtrado local sin llamadas adicionales al backend
  - Reagrupación automática de datos al cambiar filtro
- **Corrección de Visualización**: Ajustadas configuraciones de ApexCharts para evitar overflow de etiquetas del eje X.
  - Aplicado en gráficos de "Evolución de Tareas" y "Rendimiento de Tareas"
  - Configuraciones: `chart.offsetY: -10`, `chart.parentHeightOffset: 0`, `xaxis.labels.offsetY: -5`

#### [FIX] Corrección de Campos Nulos en Job Queue
- **Problema**: Los campos `result`, `worker_id`, `duration` y `stack_trace` siempre quedaban en `null` al procesar tareas.
- **Solución**: Actualizado `SchedulerService` para capturar y guardar correctamente estos campos:
  - **`duration`**: Calculado midiendo tiempo de inicio y fin de ejecución (en milisegundos)
  - **`workerId`**: Generado automáticamente basado en `hostname-PID` (ej: `DESKTOP-ABC-12345`)
  - **`result`**: Captura del valor retornado por el procesador de tareas
  - **`stackTrace`**: Guardado completo de `error.stack` cuando hay errores (no solo el mensaje)
- **Mejora en Procesadores**: `VesselSyncProcessor` ahora retorna información útil sobre la sincronización ejecutada (vesselId, vesselName, mmsi, syncedAt).
- **Impacto**: Mejor diagnóstico de tareas, métricas precisas de rendimiento, y debugging facilitado con stack traces completos.

#### [FEAT] Reingeniería y Unificación de Alertas de Marea
- **Centralización de Inteligencia**: Nueva arquitectura basada en `EventCorrelationService` que unifica las reglas de negocio entre Tracking CSV y API PNA.
- **Source Stacking Robusto**: Implementada deduplicación inteligente que permite que múltiples fuentes (satelital y oficial) validen una misma alerta sin duplicarla, acumulando historial de evidencia.
- **Integridad Ferroviaria de Puertos**: Refactorización del motor de correlación para priorizar estrictamente los IDs del catálogo de puertos sobre los nombres comerciales, eliminando falsos positivos en puertos con nombres idénticos pero ubicaciones distintas.
- **Alertas Especializadas**: 
  - **Discreparancia de Puerto**: Generada cuando hay una diferencia de ubicación basada en IDs técnicos.
  - **Incongruencia de Fecha**: Detectada cuando la jornada local del evento no coincide con la registrada.
  - **Recomendación de Fin de Marea**: Sugerencia proactiva para cerrar mareas antiguas si se detecta un arribo y existe una nueva marea designada.

#### [QUALITY] Pruebas Unitarias y Estabilización Técnica
- **Suite de PNA API Service**: Implementada nueva suite integral `pna-api.service.spec.ts` con 13 casos de prueba cubriendo deduplicación, auditoría y reglas de negocio.
- **Estabilización de Matching V2**: Actualizados tests de `tracking.matching_v2.spec.ts` para cumplir con los nuevos estándares de integridad de puertos por ID.
- **Cobertura Global**: Se alcanzó un hito de **139 tests pasando con 100% de éxito**, garantizando la estabilidad del núcleo de gestión de mareas.
- **Arquitectura de Mocks**: Refactorización del `beforeEach` en tests críticos para asegurar aislamiento total y evitar persistencia de estados entre ejecuciones.
